以内网中一台可以访问外网的服务器为例。远程使用时，先让内网服务器主动连到阿里云服务器，建立反向 SSH 隧道，再从本地电脑通过阿里云跳板登录内网服务器。
连接经过以下几个位置：

```text
本地电脑 → 阿里云 :22 → 阿里云 127.0.0.1:10001 → 内网服务器 :22
```

10001 只监听阿里云的回环地址，本地电脑通过阿里云的 SSH 入口访问这个端口。进入内网服务器时，还要通过内网服务器自己的 SSH 认证。
下面以阿里云上的 Ubuntu 22.04 和内网服务器上的 Rocky Linux 8.10 为例。`a.a.a.a` 代表阿里云公网 IP，`remoteuser` 是内网服务器的示例登录用户名，示例中的地址和密钥路径需要替换成自己的配置。
开始前，确保内网服务器已安装 autossh，阿里云已安装 Fail2ban。

## 1. SSH 入口与密钥

需要准备两条连接的密钥认证：内网服务器到阿里云，以及本地电脑经阿里云到内网服务器。每台发起连接的机器保留自己的私钥，把对应公钥加入接收端账号的 `~/.ssh/authorized_keys`。
例如，查看已有 RSA 密钥的公钥：

```bash
cat ~/.ssh/id_rsa.pub
```

登录接收端账号后，准备文件并追加公钥，每把公钥单独占一行：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
vi ~/.ssh/authorized_keys
```

如果安装了 `ssh-copy-id`，也可以从发起端直接添加，例如：

```bash
ssh-copy-id -i ~/.ssh/id_rsa.pub root@a.a.a.a
```

本地电脑的公钥需要分别加入阿里云账号和内网服务器的 `remoteuser` 账号。内网服务器上运行隧道的账号也需要能用自己的密钥登录阿里云。
示例使用阿里云的 `root` 账号。它拥有整台跳板机的管理权限，隧道所用私钥也能取得这个权限，需要妥善保管。多人使用时，应为转发另建受限的普通账号。
阿里云本机的其他进程也能访问回环端口，因此仍需保护跳板机上的账号和服务。

在阿里云上编辑 `/etc/ssh/sshd_config` 中对应的配置项：

```text
AllowTcpForwarding yes
GatewayPorts no
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
```

`GatewayPorts no` 将反向转发的监听范围限制在回环地址，配合后面的 `127.0.0.1:10001` 使用。[OpenSSH 文档](https://man.openbsd.org/sshd_config#GatewayPorts)说明了这个选项的行为。
先保留当前 SSH 会话，另开窗口验证密钥登录成功，再关闭密码认证。修改后检查配置并重新加载：

```bash
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -e '^gatewayports ' -e '^allowtcpforwarding ' -e '^passwordauthentication ' -e '^kbdinteractiveauthentication '
```

最后一条命令应显示 `gatewayports no`、`allowtcpforwarding yes`，以及两项密码相关认证均为 `no`。阿里云安全组和 UFW 需要为这条连接放行 `22/tcp`；10001 用于回环访问，无需添加公网入站放行规则。

```bash
sudo ufw allow 22/tcp
sudo ufw status verbose
```

## 2. 建立反向隧道

在内网服务器上，先切换到运行隧道的账号。下面的 systemd 服务使用 `root`，所以首次连接验证和隧道进程都使用内网服务器上的 `root` 密钥及 `known_hosts`。
先手动登录阿里云，核对并保存主机指纹，确认密钥认证可用：

```bash
ssh root@a.a.a.a
```

退出这次连接，回到内网服务器后启动隧道：

```bash
autossh -M 0 -NT \
    -o ServerAliveInterval=30 \
    -o ServerAliveCountMax=3 \
    -R 127.0.0.1:10001:127.0.0.1:22 \
    root@a.a.a.a
```

`-R` 前面的 `127.0.0.1:10001` 是阿里云上的监听地址，后面的 `127.0.0.1:22` 是内网服务器上的 SSH 服务地址。两个回环地址分别属于这两台机器。
`-NT` 表示只做转发。`-M 0` 关闭 autossh 的额外监测端口，连接故障由 SSH 的保活参数检测，SSH 退出后再由 autossh 重连，具体机制见 [autossh 说明](https://www.harding.motd.ca/autossh/README.txt)。

在阿里云上检查：

```bash
sudo ss -lntp '( sport = :10001 )'
```

应看到 `127.0.0.1:10001` 处于 `LISTEN` 状态，监听进程为 `sshd`。端口监听成功后，再从本地测试完整的跳板连接。

## 3. 通过跳板登录内网服务器

在本地 SSH 配置中添加两个别名。Linux 和 macOS 的配置文件为 `~/.ssh/config`，Windows 为 `C:\Users\用户名\.ssh\config`：

```sshconfig
Host jump-server
    HostName a.a.a.a
    Port 22
    User root
    IdentityFile ~/.ssh/id_rsa
    IdentitiesOnly yes
    ForwardAgent no

Host remote-server
    HostName localhost
    Port 10001
    User remoteuser
    ProxyJump jump-server
    IdentityFile ~/.ssh/id_rsa
    IdentitiesOnly yes
    ForwardAgent no
```

这里的 `localhost:10001` 由跳板机访问，对应阿里云上的反向隧道入口。本地客户端经 `ProxyJump` 建立到内网服务器的 SSH 连接，内网服务器的认证仍由本地客户端完成，私钥留在本地。[ProxyJump 文档](https://man.openbsd.org/ssh_config#ProxyJump)介绍了这种连接方式。
`IdentitiesOnly yes` 让客户端使用指定密钥，减少 SSH agent 中其他密钥带来的无效尝试。

先测试跳板，再测试内网服务器：

```bash
ssh jump-server
ssh remote-server
```

两条命令需要分别执行，第一条验证后先退出阿里云会话，再在本地执行第二条。也可以在本地直接使用：

```bash
ssh -J jump-server -p 10001 remoteuser@localhost
```

首次连接时，需要分别核对阿里云和内网服务器的主机指纹。可以通过各自控制台或已信任的连接，在对应服务器上查看公钥指纹：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

确认连接成功后，VS Code Remote SSH 也可以直接选择 `remote-server`。

## 4. 访问内网服务器的 Web 应用

假设内网服务器上的应用监听 `127.0.0.1:5010`，在本地执行：

```bash
ssh -NT -L 127.0.0.1:8080:127.0.0.1:5010 remote-server
```

随后在本地浏览器打开 `http://127.0.0.1:8080`。8080 只监听本地电脑的回环地址，5010 则由内网服务器上的 SSH 服务访问。
保持这个 SSH 进程运行，浏览器访问期间转发才会持续。

## 5. 让隧道随系统启动

在内网服务器上建立 `/etc/systemd/system/autossh-tunnel.service`，`ExecStart` 中的地址仍需替换为自己的阿里云公网 IP：

```ini
[Unit]
Description=AutoSSH tunnel for internal server
After=network-online.target
Wants=network-online.target

[Service]
User=root
Group=root
Environment="AUTOSSH_GATETIME=0"
ExecStart=/usr/bin/autossh -M 0 -o "ServerAliveInterval 30" -o "ServerAliveCountMax 3" -NTR 127.0.0.1:10001:127.0.0.1:22 root@a.a.a.a
Restart=always
RestartSec=60

[Install]
WantedBy=multi-user.target
```

先用 `command -v autossh` 确认程序路径。systemd 负责管理前台进程；`AUTOSSH_GATETIME=0` 让 autossh 在首次连接失败后也继续重试。
启动服务前，结束前面手动启动的 autossh，避免两个进程争用同一个转发端口。然后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable autossh-tunnel.service
sudo systemctl restart autossh-tunnel.service
sudo systemctl status autossh-tunnel.service
```

如果服务已有 override，可以连同它一起查看，并确认最终生效的命令：

```bash
sudo systemctl cat autossh-tunnel.service
sudo systemctl show autossh-tunnel.service -p ExecStart
sudo journalctl -u autossh-tunnel.service -n 50 --no-pager
```

最终命令中的转发地址应为 `127.0.0.1:10001:127.0.0.1:22`。在阿里云重新检查监听地址，再从本地新建一次内网服务器连接，才能确认整条链路正常。

## 6. 用 Fail2ban 限制 SSH 扫描

阿里云的 SSH 入口使用公钥认证，再配合 Fail2ban 限制无效用户和认证失败的重复尝试。下面以 Fail2ban 0.11.2 为例：10 分钟内失败 10 次，封禁 10 分钟，封禁时间不递增。
白名单包含已确认的本地公网出口和内网服务器所在网络的公网出口。下面使用 `b.b.b.b` 和 `c.c.c.c` 作为这两个出口的示例，需要先替换成自己实际的公网地址。

在阿里云的 SSH 会话中，可以查看当前连接来源，第一列就是本次连接的来源 IP：

```bash
printf '%s\n' "$SSH_CONNECTION"
```

内网服务器的公网出口可以在阿里云的 SSH 登录日志中确认。公网出口变化后，需要更新白名单。
在阿里云上编辑 `/etc/fail2ban/jail.d/99-sshd-safe.local`：

```ini
[sshd]
enabled = true
backend = systemd
journalmatch = _SYSTEMD_UNIT=ssh.service + _COMM=sshd
filter = sshd[mode=normal, publickey=nofail]
port = 22
protocol = tcp
chain = INPUT
usedns = no
ignoreself = true
ignoreip = 127.0.0.1/8 ::1 b.b.b.b c.c.c.c
findtime = 10m
maxretry = 10
bantime = 10m
bantime.increment = false
bantime.rndtime = 0
action = iptables-sshd-new[name=sshd, port=22, protocol=tcp, chain=INPUT, actionstart_on_demand=false]
```

这份配置读取阿里云的 SSH 日志，保护入口 `22/tcp`。`publickey=nofail` 让有效用户名的普通公钥尝试不计为认证失败；触发 SSH 最大认证尝试次数限制的事件仍会计数，规则可参阅 [Fail2ban SSH 过滤器](https://github.com/fail2ban/fail2ban/blob/0.11/config/filter.d/sshd.conf)。
`iptables-sshd-new` 是额外定义的动作。在阿里云创建 `/etc/fail2ban/action.d/iptables-sshd-new.conf`：

```ini
[INCLUDES]
before = iptables-multiport.conf

[Definition]
actionstart = <iptables> -N f2b-<name>
              <iptables> -A f2b-<name> -j <returntype>
              <iptables> -I <chain> -p <protocol> -m multiport --dports <port> -m conntrack --ctstate NEW -j f2b-<name>

actionstop = <iptables> -D <chain> -p <protocol> -m multiport --dports <port> -m conntrack --ctstate NEW -j f2b-<name>
             <actionflush>
             <iptables> -X f2b-<name>
```

它沿用标准的封禁和解封动作，在进入封禁链之前增加 `--ctstate NEW`，只拦截新建连接。已建立的 SSH 会话可以继续使用，误封时仍能在原会话中解封。
启用前保留一个已登录的窗口，先留好退路，别问我怎么知道会被关在外面。先检查配置：

```bash
sudo fail2ban-client -t
```

检查成功后，安排一个 10 分钟后自动停用 Fail2ban 的临时任务，再启用服务：

```bash
sudo systemd-run --unit=fail2ban-safety-rollback --on-active=10m /usr/bin/systemctl disable --now fail2ban
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
```

如果 Fail2ban 原本已经运行，修改配置后在回退任务保护下执行 `sudo systemctl restart fail2ban`，让新配置生效。
另开窗口，从本地分别新建到阿里云和内网服务器的 SSH 连接。确认服务正常、白名单正确、两次连接均成功后，取消临时回退：

```bash
sudo fail2ban-client get sshd ignoreip
sudo systemctl stop fail2ban-safety-rollback.timer
```

需要立即解封时，在保留的 SSH 会话或阿里云控制台登录后执行，将示例地址替换为被封的实际来源：

```bash
sudo fail2ban-client set sshd unbanip b.b.b.b
```

Fail2ban 的这一组规则只管理阿里云 SSH 入口。进入内网服务器后使用的账号权限和认证方式，仍由内网服务器自己的 SSH 配置决定。
